## Global constraints

- **Determinism law.** No `Math.random`, `Date.now`, `performance.now`, or `.mesh` in any new or modified sim code. Use `proj.x/z`, `combatant.paddleZ`, `combatant.prevPaddleZ`. Never `proj.mesh.position` or `paddle.position` inside `js/sim.js`.
- **SP feel wins.** Every reconciliation in Task A resolves to SP's value. If a test or playtest reveals a feel regression, SP's old value is correct — diagnose and patch the sim.
- **The oracle is the gate for Task A.** Never pin G_2.3 until the numeric correctness tests (A.12) AND the SP-feel playtest (A.13, lead-run) both pass.
- **The SP-feel playtest is the gate for Task C.** Never commit the driver swap until the lead has played SP before and after and confirmed feel parity.
- **Do NOT delete the old singles loop until Task D.** Task C makes the two paths mutually exclusive (the accumulator branch); both must coexist until Task D is committed. This gives a rollback point if the feel-gate fails.
- **Doubles path is read-only.** `isDoublesMode()` branches inside `updateGameLogic` are never touched in this plan.
- **FX via deps only in the sim.** Every new presentation call in `js/sim.js` goes through `ctx.deps.*` and is gated by `if (!isResimulating)`. No direct Babylon, DOM, or audio calls.
- **Bump `?v=` on `js/sim.js` after every edit.** The `<script type="module" src="js/sim.js?v=...">` tag at index.html:599 must have a fresh cache-buster on every sim edit, or browsers serve a stale module.
- **Subagents only run `node --check` and purity greps.** Browser oracle runs and SP playtests are run by the lead.
- **Append-only working log.** After Task E, append a dated entry to `docs/agents/gameplay-combat.md`.
